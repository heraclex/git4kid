01 · Start with a simple story

Ever had files like these?

Imagine you're creating a computer game. You write some code, change it, add new features, and sometimes accidentally break things. Without Git, you might end up with:

my-game/
  my-game-final.py
  my-game-final-v2.py
  my-game-final-fixed.py
  my-game-final-really-final.py
We've all seen this problem! 😅

Which file is the newest? Which one works? Git (and GitHub) solve this by saving the history of your project and helping people collaborate.

01 · One important distinction

Git vs GitHub

🕰️

Git

The tool that tracks changes in your code.

Tracks history
Runs on your computer
🐙

GitHub

A website / platform that hosts Git projects and makes collaboration easier.

Hosts repositories
Helps teams collaborate

An easy sentence to remember:
Git is the time machine. GitHub is the place where developers share their time machines and work together.

02 · Introduce the four most important concepts

The starter pack — only these four

📁

1. Repository (Repo)

A project folder containing all your files and the history of changes.

Example: a repository called my-first-game.
📸

2. Commit

A saved checkpoint of your project.

Example: “I added a player character.”
🌿

3. Branch

A separate workspace where you can experiment without changing the main version.

Example: try adding a new game level.
🔀

4. Pull Request (PR)

A proposal to merge your changes into the main project.

Example: “I've finished the new level. Can we add it to the game?”

03 · Let's do a small practical demo · Step 1 of 5

Create a GitHub account & your first repo

Beginner friendly · No coding required. We'll use the GitHub website — no installing, no terminal.
The mission: create your first project and change it three times, just like a real developer.

Go to github.com and create a free account. Then:

Click the + button in the top-right corner.

Select New repository.

Name it my-first-project.

Choose Public (so you can share it).

Tick Add a README file.

Click Create repository.

03 · Step 1 · Safety first

🎉 You've created your first repository!

Safety tip: a public repository can be seen by anyone. Never publish passwords, private information, your home address, or anything you want to keep private.

Next up: save your first checkpoint.

03 · Step 2 of 5 · First checkpoint

Make your first commit

Open the README.md file and click the pencil icon to edit it. Add this content (replace Alex with your name):

# My First Project

Hello! My name is Alex.

I am learning GitHub.

## My interests
- Gaming
- Football
- Programming

## My goal
Build my first computer game!

Scroll to the commit section. Commit message: Create my first README → click Commit changes.

“You've just saved a checkpoint. GitHub remembers what your project looked like at this moment.” 📸

03 · Step 3 of 5 · Build the history

Change something and commit again

Edit README.md again. Add:

## My favourite games
- Minecraft
- Roblox
- Fortnite

Commit with this message: Add my favourite games

Commit 1
Create my first README
→
Commit 2
Add my favourite games

Now you have two commits. Open the repository's commit history and see how GitHub remembers both versions.

The interesting part: if you accidentally delete something, you can look at the previous commit and recover your earlier work. ⏪

03 · Step 4 of 5 · Experiment safely

Introduce branching

Pretend you want to add a new feature. Instead of modifying the main project directly:

  1. Go to the repository's branch selector.
  2. Create a new branch called add-my-hobbies.
  3. Edit README.md on that branch.
  4. Add a new section (right).
  5. Commit the changes.
## My hobbies
- Playing football
- Building LEGO
- Playing video games
main ──●──●─────────
add-my-hobbies ───╰──●

The main branch hasn't been changed. The new work lives separately.

03 · Step 5 of 5 · Ask to combine the work

Create a Pull Request → Merge

This is where GitHub becomes interesting.

Go to the Pull requests tab and click New pull request.

Select Base: main and Compare: add-my-hobbies. You should see the changes you made.

Give it a title: Add my hobbies to the project

Click Create pull request.

Finally, click Merge pull request and confirm.

“You're asking the project owner to review your work before adding it to the main project.”

Now let's play with real Git 🎴

We've prepared a tiny project called Hero Card Studio. You create your own copy from playground.bundle, and it comes with a ready-made Git history. You design a hero card in your browser — and use Git to save it, break it, rescue it, and explore alternate universes.

💥

It starts broken

Someone saved a bad change. Can you find it?

⏪

Time travel

Undo the mistake without losing history.

🌿

Parallel universes

Hero vs villain, on separate branches.

Needs Git installed (git --version in a terminal) and any web browser. Full instructions are in MISSIONS.md inside the playground.

05 · Setup (2 minutes)

Get the playground ready

Open a terminal (Mac: Terminal app · Windows: Git Bash) in the folder with this presentation, and create your copy:
git clone playground.bundle playground
cd playground

Tell Git who you are, once:
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Open index.html in your browser. You should see 💥 The card is broken!

Open character.js in any text editor (Notepad, TextEdit, VS Code…).

Mission 1 & 2 · The time machine

📖 Read history, then ⏪ undo the oops

git log --oneline

Each line is a commit. Find “Oops: tidy up character file” and note its short code.

git show <code>
git revert <code> --no-edit

Refresh index.html — Captain Pixel is back! Git added a new commit that reverses the mistake. Nothing was erased.

Mission 3 · Make it yours

🦸 Design your hero

Edit character.js: change the name, emoji, power, color (e.g. #ff8eae) and motto. Save, refresh the browser, admire. Then save a checkpoint:

git diff                      # what did I change?
git add character.js
git commit -m "Make the hero mine"

Tip: git diff is like “track changes” — it shows exactly what you changed since the last checkpoint.

Mission 4 & 5 · Parallel universes

🌿 Hero vs 😈 Villain

git switch -c evil-mode
# make your hero a villain!
git commit -am "Turn to the dark side"
git switch main

Refresh — your hero is back, untouched! git switch evil-mode brings the villain back.

Like the villain better? Merge it (this is what a Pull Request does on GitHub):

git switch main
git merge evil-mode

Don't like it? Skip the merge. main stays safe.

06 · What to learn next

A natural learning path

GitHub basics: repository, commit, branch, pull request.

Git locally: install Git and learn git add, git commit, git push, git pull.

Programming: learn Python or JavaScript.

Build something: a small calculator, quiz game, or website.

Collaboration: work with another person on the same project.

Once you understand the GitHub website, you're ready for real programming and Git commands.

Final thought

Motivation beats memorizing commands

Build something you genuinely enjoy — such as a Minecraft-inspired game or a personal website.
